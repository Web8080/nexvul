# NEX007 - MCP connection without authentication or over cleartext

| Field | Value |
|---|---|
| ASI labels | ASI07 (primary), ASI04 - `docs/owasp/mapping.md` |
| CWE | CWE-319 (cleartext transmission), CWE-306 (missing authentication) |
| Detection class | config (literal values in client configs and constant call arguments) |
| Status | **Experimental thin slice** (Phase 2 step 4, 2026-10-13). Off by default: the benchmark holds fewer than 20 labelled cases (DEC-0002). Enable with `rules.enabled: [NEX007]` in `.nexvul.yml` (or `[ASI07]`). |
| Code | `src/nexvul/rules/asi07/nex007.py`, `src/nexvul/frameworks/mcp/` |
| Tests | `tests/rules/nex007/` (42 fixture cases), `tests/unit/test_nex007.py`, `tests/unit/test_parser_json.py` |
| Benchmark | `benchmarks/{vulnerable,safe,adversarial}/NEX007/` (15 cases); `python benchmarks/run.py` |

A finding reports a risky configuration. It does not prove that anyone can intercept the traffic or
call the server, and a scan with no NEX007 finding does not prove that MCP connections are protected.

## What it reports

| Condition | Severity | Confidence |
|---|---|---|
| HTTP or SSE MCP server entry whose literal `url` is `http://` to a host that is not loopback, **with or without** credentials configured | high (medium for a private-network host) | high |
| Same, `https://` to a non-loopback host, and **no authentication indicator in the same entry** | medium (low for a private-network host) | medium |
| Python `mcp` SDK `streamablehttp_client()` / `streamable_http_client()` / `sse_client()` with a constant URL meeting either condition | as above | as above |

Confidence is capped at **medium** when the file was recognised by structure only (an unknown client file with
an `mcpServers` object), for Claude Desktop configs (the research did not verify that Claude Desktop uses `url`
entries from that file), and when the evaluated key or server name is duplicated in the file.

Message example (cleartext, no auth):

> The MCP server entry 'search' in .cursor/mcp.json uses an HTTP transport at http://mcp.example.com/mcp,
> over cleartext http:// to a non-loopback host. No authentication setting (headers, auth block,
> bearer/OAuth) was found in this config entry.

Each finding carries three evidence items: how the file was recognised (client and servers key), the JSON
Pointer and the displayed URL with the transport, and the list of authentication settings looked for and found
(names only).

## The nine questions (brief §17)

### 1. Source

None: this is a config rule. The "input" is the literal configuration: the `url` value of an MCP server entry
in a client config file, or a string-constant URL passed to a Python SDK client function.

### 2. Sink

The MCP client connection itself:

- Config files (recognised by file name **and** structure; see `src/nexvul/frameworks/mcp/config.py`):

  | File | Servers key | Client |
  |---|---|---|
  | `claude_desktop_config.json` | `mcpServers` | Claude Desktop |
  | `.mcp.json` | `mcpServers` | Claude Code project scope (also read by VS Code) |
  | `.cursor/mcp.json` | `mcpServers` | Cursor |
  | `.vscode/mcp.json` | `servers` | VS Code |
  | `.copilot/mcp-config.json` | `mcpServers` | Copilot |
  | any other `*.json` | `mcpServers` | unknown client (structure only, medium confidence) |

  The servers key must hold an object, and at least one entry must be an object with a string `command` or
  `url`. Transport: `type`/`transport` `http`, `streamable-http`, `streamableHttp` -> HTTP; `sse` -> SSE;
  `stdio` -> stdio; no type -> stdio when `command` is present (Claude Code's default), else HTTP; any other
  type -> unknown (not reported).
- Python: `mcp.client.streamable_http.streamablehttp_client`, `mcp.client.streamable_http.streamable_http_client`
  and `mcp.client.sse.sse_client`, resolved through imports (aliases and module aliases work).

### 3. Dangerous flow

There is no data flow. The dangerous pattern is the literal combination *remote destination* + *cleartext
transport*, or *remote destination* + *no authentication configured in this entry*.

"Remote" means the URL host is not loopback and not the unspecified address. Loopback: `localhost`,
`*.localhost`, `127.0.0.0/8` in any WHATWG spelling (`127.1`, `0x7f.0.0.1`, `2130706433`), `::1`,
`::ffff:127.x.x.x`, percent-encoded forms (`local%68ost`), a trailing dot (`localhost.`). `0.0.0.0` and `::`
as a *client destination* reach the local machine and are not reported. Private-network hosts (RFC 1918, ULA,
link-local, single-label names such as a compose service `mcp`, `.local`, `.internal`, `.lan`, `.home.arpa`,
`.svc`, `.cluster.local`) are still reported, one severity step lower.

Authentication indicators (any one suppresses the "no auth" finding for `https://`; none suppresses the
cleartext finding):

- a `headers` (or `requestInit.headers`) entry whose name contains `auth`, `token`, `key`, `secret`,
  `session`, `cookie`, `bearer`, `credential`, `password` or `signature`, with a non-empty value;
- any header whose value is a variable reference (`${VAR}`, `${env:X}`, `${input:id}`, `{{x}}`);
- an entry key containing `auth`, `token`, `bearer`, `apikey`, `secret`, `credential`, `password` or
  `headershelper` with a non-empty value (`auth`, `oauth`, `authorization_token`, `headersHelper`, ...);
- user-info in the URL (`https://user:pass@host`) or a credential query parameter (`?token=`, `?api_key=`);
- Python: a `headers`, `auth`, `http_client` or `httpx_client_factory` argument that is not `None`, or a second
  positional argument.

The indicator list is deliberately lenient (an unknown auth-looking key counts as auth): the rule prefers to
miss than to report a configured server.

### 4. What makes it dangerous

A remote MCP server's tools run with the authority the client grants them, and tool descriptions and results
flow into the model's context. Over cleartext `http://`, anyone on the network path can read or rewrite tool
descriptions, calls and results (OWASP ASI07 scenario 1, semantic injection via unencrypted communications) and
capture any token sent. Without authentication, anyone who can reach the server can call its tools, and the
client cannot tell a spoofed server from the real one. The MCP authorization spec requires bearer tokens in
the `Authorization` header and never in the query string; MCP's security best practices recommend
token-protected HTTP or stdio for local servers.

Authorization is **optional** in the MCP spec, so a missing auth setting is a risk, not a spec violation.

### 5. Legitimate look-alikes (false-positive risks)

| Look-alike | Handling |
|---|---|
| Local development servers (`http://localhost:8000/mcp`) | Not reported (loopback). |
| Stdio servers, including unpinned `npx -y` (the official quickstart pattern) | Not reported: NEX007 is about remote channels; supply-chain risk is a separate concern. |
| `https://` server that uses OAuth discovered at connect time (protected-resource metadata, RFC 9728) | **Reported at medium/medium** - the config has no auth setting, and a static scan cannot see what the server will negotiate. This is the largest expected FP source; the message says so. |
| Auth enforced by a gateway, VPN or mesh in front of the server | Reported (cannot be seen). Private-network hosts get one severity step lower. |
| TLS-terminating sidecar for `http://svc.cluster.local` | Reported as cleartext, medium severity (private network). |
| Claude Desktop config with a `url` entry the client may ignore | Reported, confidence capped at medium. |
| A JSON file named `mcp.json` that is not an MCP config | Not reported: structure is required. |
| `servers` object outside `.vscode/mcp.json` | Not recognised. |

Benchmark FPs on the current corpus: 0 (see "Measured" below).

### 6. Evasion (false negatives)

| Evasion | Status |
|---|---|
| URL from an environment variable / `${VAR}` / `${VAR:-default}` | Not reported (host unknown). Known FN. |
| Python URL held in a variable or module constant, f-string, `**kwargs` | Not reported. Known FN (`tests/rules/nex007/adversarial/case_011`, benchmark BM-NEX007-0202). |
| `langchain_mcp_adapters.MultiServerMCPClient({...})` dict literal | Not reported: the IR keeps a 200-character rendering of the dict, not its structure. Known FN (`case_012`). |
| Windsurf `serverUrl`, Zed, Continue, Cline, Gemini CLI, Codex `config.toml` shapes | Not recognised (UNVERIFIED in research). Known FN (`case_013`). |
| Duplicate keys (`"url": "https://..."`, `"url": "http://..."`) | The last occurrence is evaluated (as `JSON.parse` does) with confidence medium; an overridden duplicate server entry is still evaluated, confidence medium. |
| Upper-case scheme or type, trailing dots, IPv6 literals, numeric IPv4 spellings | Normalised before classification. |
| `localhost.attacker.example`, `127.0.0.1.attacker.example` | Reported: these are remote names. |
| Declaring `"type": "stdio"` next to a `url` | Not reported: the client launches the command and does not use the URL. |
| Comments or trailing commas in a JSON file | Read as JSONC; the finding is still produced. |
| A JSON syntax error, a file over 1 MiB, nesting over 100 | The file is not analysed and the scan is PARTIAL (never silently clean). |

### 7. Evidence shown

The JSON Pointer of the `url` (e.g. `/mcpServers/search/url`), the URL as displayed (user-info and query values
removed, secret-shaped strings redacted), the transport and declared type, the recognised client, and the names
of the authentication settings searched for and found. Header **values**, user-info and query values are never
copied into findings: a literal token in a committed config is not echoed (tested in
`tests/unit/test_nex007.py::test_literal_secret_is_never_echoed`). Every repository-derived string (server
names, paths) is sanitised; hostile names with ANSI escapes, newlines or bidi controls are shown escaped.

### 8. Confidence

- high: literal `http://` URL to a non-loopback host in a recognised client config, or a constant URL passed to an
  import-resolved SDK function (taxonomy §3.2, literal config).
- medium: `https://` with no auth setting (absence of a control in this file only - OAuth may be negotiated at
  connect time); structure-only recognition; Claude Desktop; duplicated keys or server names.

### 9. What it does NOT detect

- Authentication configured outside the file: on the server, in a gateway or reverse proxy, or negotiated by
  OAuth at connect time.
- Configs generated at runtime, servers added through a client CLI or UI (`claude mcp add`, Cursor settings UI),
  and client configs outside the repository (`~/.claude.json`, `~/.cursor/mcp.json`, IDE user settings).
- Env-driven URLs, URLs built in code, YAML/TOML configs, TypeScript MCP clients, MultiServerMCPClient.
- MCP **servers** bound to `0.0.0.0` without auth (taxonomy lists it as a NEX007 sink; not in this slice).
- Malicious tool descriptions (tool poisoning), token passthrough, weak or leaked credentials, broad OAuth
  scopes, tokens in URLs on `https://` (reported nowhere yet), unpinned `npx -y` packages.

## Suppressing a finding

JSON has no comments, so inline suppression cannot apply to `.json` configs (the architecture defines inline
suppressions only; there is no config-level per-finding suppression yet). Options:

- exclude the file in `.nexvul.yml` (`exclude: [path/to/mcp.json]`), or
- disable the rule (`rules: {disabled: [NEX007]}`) - in CI, repo config can only tighten (DEC-0004 §1), so
  this is ignored there and reported as a weakening change.

Python findings use the normal inline form:

```python
async with streamablehttp_client("http://10.0.0.2/mcp") as s:  # nexvul: ignore[NEX007] -- lab network, no secrets
```

## Examples

Flagged (high/high):

```json
{ "mcpServers": { "search": { "type": "http", "url": "http://mcp.example.com/mcp" } } }
```

Flagged (medium/medium):

```json
{ "servers": { "kb": { "type": "http", "url": "https://kb.example.com/mcp" } } }
```

Not flagged:

```json
{
  "mcpServers": {
    "search": { "type": "http", "url": "https://mcp.example.com/mcp",
                "headers": { "Authorization": "Bearer ${MCP_TOKEN}" } },
    "files":  { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem"] },
    "dev":    { "type": "http", "url": "http://localhost:8000/mcp" }
  }
}
```

## JSON parsing (what nexvul reads from `.json` files)

`src/nexvul/parser/json_config.py`, in the isolated parse workers: UTF-8 only (a UTF-8 BOM is accepted;
UTF-16/32 is `non_utf8_undecodable`), 1 MiB file cap, nesting cap 100 (checked by an iterative tokenizer before
the stdlib parser runs), at most 100,000 values, numbers longer than 100 characters rejected, `NaN`/`Infinity`
rejected, duplicate keys recorded (never resolved by the parser), JSONC comments and trailing commas accepted and
noted, strings capped at 10,000 characters. The stdlib `json` module re-parses the text as the authoritative
syntax check. `${VAR}` references are kept as text, never expanded; `envFile` and other referenced files are
never read. A `.json` file in which no recogniser finds anything counts as analysed (not partial).
